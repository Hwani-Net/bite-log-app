# 기록의 무게 개선 리스트 (5차)

작성 2026-08-28. 1~4차 완료 후 남은 백로그를 "조과 기록 층 강화" 축으로
묶은 것. 조사 원문(2026-08-28 전수 조사)과 3·4차 실행 중 발견이 소스.

## 결 (전략)

이 앱의 유일한 해자는 사용자의 기록이다 — 예보는 누구나 API로 만들지만
"내 3년치 조과"는 BiteLog에만 있다. 그런데 그 기록 층에 실손실 리스크
(사진 3장이면 Firestore 1MiB 문서 한계 초과로 저장 실패 가능)와 품질
구멍(1년 뒤 다시 읽을 가치를 만드는 채비 필드 부재, 어종 칩이 메모까지
매칭하는 검색, 14필드 중 7필드만 나가는 내보내기)이 남아 있다. 기록이
무거워질수록 앱을 떠나기 어려워진다 — 이번 축은 그 무게를 만든다.

## R. 기록 층

| # | 항목 | 내용 |
|---|------|------|
| R1 | 기록 목록·편집 정리 | 어종 칩이 free-text 검색 문자열에 합쳐져 메모의 "우럭"도 매칭(필드 전용 필터로 분리). 날짜 범위·사진만 필터 부재. CSV 내보내기가 14필드 중 7필드(날씨·물때·공개여부·배·시각 누락). 상세 편집에 사진 추가/삭제 없음 |
| R2 | 채비·미끼 필드 | memo가 유일한 탈출구 — "그날 뭘로 잡았나"가 기록의 재독 가치 핵심인데 구조화 필드가 없다. tackleAdviceService 어휘(440줄, 단일 소비자)로 자동완성 |
| R3 | 사진 → Firebase Storage | 사진이 base64로 Firestore 문서에 들어감 — 3장이면 1MiB 문서 한계 초과로 저장 실패 가능(실손실 리스크). 클라이언트 압축+Storage 업로드+URL 저장, 기존 base64 렌더 호환, 오프라인 폴백 유지 |
| R4 | 랭킹 정직화 | 기본값이 비공개인 기록은 랭킹에 안 잡혀 리더보드가 "공개 의지" 순위가 됨 — 미반영 안내+원탭 공개. computeBadges가 있는데 랭킹 배지는 하드코딩 빈 배열. 지역별 랭킹(region은 피드에 이미 있음) |
| R5 | 컨시어지·홈 마무리 | AI 채팅이 새로고침에 날아감(useState만). generateCatchReport는 작성돼 있는데 0 호출 — "조황 리포트" FAB은 stats로 도망감. 홈 햄버거는 클릭 핸들러 없는 장식 3줄 |
| R6 | apiFetch 규칙 정합 | CLAUDE.md가 apiFetch/apiError 사용을 명령하는데 0 importer, 25개 raw fetch — 규칙과 코드 중 하나는 거짓말. 채택 범위를 정해 집행하거나 규칙을 현실로 수정 |

## 보류 (이번 축 아님)
