# Change Brief — 표시 어종 확대

**요청(2026-08-28)**: "표시 어종이 너무 부족한데?" — 예약 화면 기준.

## 로컬 스캔 결과 (실측)

어종 목록이 앱 안에 다섯 벌로 흩어져 있고, 화면에 가장 크게 노출되는 곳이
그중 제일 작은 목록을 쓴다.

| 소스 | 개수 | 쓰이는 곳 | 성격 |
|---|---|---|---|
| `FISH_SEASON_DB` (fishSeasonDB.ts) | **5** | booking 「어종으로 찾기」, season-forecast | FIRA 방류계획 실데이터 |
| `SPECIES_LIST` (fishSpecies.ts) | 9 | trip-plan | 손으로 적은 목록 |
| `SPECIES_FILTERS` (boatListingService.ts) | 12 | booking 어종 필터 | 더피싱 `si[]` 코드 |
| `FISH_SPECIES` (types/index.ts) | 13+기타 | 기록 입력 | 손으로 적은 목록 |
| `FISH_REGULATION_DB` | 15 | 규정 | 수산업법 실데이터 |
| `FISH_DEX_DB` | 33 | 도감 | 편집 데이터 |

`REVERSE_SPECIES_OPTIONS = FISH_SEASON_DB ∩ SPECIES_FILTERS` 라서
「어종으로 찾기」 칩이 5개(주꾸미·우럭·광어·참돔·볼락)뿐이다.

## 결정: 어디를 넓히는가

1. **`SPECIES_FILTERS`** — 더피싱의 실제 `si[]` 코드 전수를 가져와 넓힌다.
   코드가 진짜여야 검색이 실제로 동작하므로 **반드시 소스 확인**. 지어내면
   "필터를 눌렀는데 결과가 이상하다"가 된다.
2. **`FISH_SPECIES`** (기록 입력) — 우리 목록이므로 한국 바다낚시 상용 어종
   으로 넓힌다. `fishColors.ts` 가 `Record<FISH_SPECIES[number], string>` 라
   색을 빠뜨리면 컴파일이 깨진다(안전장치 유지).
3. **「어종으로 찾기」 칩** — FISH_SEASON_DB 확대는 FIRA 방류계획 전수조사가
   필요해 이번 범위 밖. 대신 칩을 `SPECIES_FILTERS` 기준으로 넓히고,
   시즌 데이터가 있는 어종만 「날짜 추천」을 제공한다. 없는 데이터를
   지어내지 않으면서 선택지는 넓어진다.

## 소스 예산

- 더피싱 검색 폼 1페이지(코드 전수). 필요 시 결과 검증용 1~2회 질의.
- 상한 3페이지. 초과하면 중단하고 현재까지 확인된 코드만 반영한다.

## 수용 기준

- 예약 화면 어종 필터가 더피싱이 실제로 제공하는 어종 수와 일치한다.
- 새로 넣은 코드로 검색했을 때 결과가 그 어종을 실제로 담고 있다(표본 검증).
- 기록 입력 어종이 넓어지고, 색 누락은 컴파일에서 잡힌다.
- 「어종으로 찾기」 칩이 넓어지되, 시즌 데이터 없는 어종에 추천 날짜를
  만들어내지 않는다.

## 중단 규칙

더피싱 코드 전수를 확인하지 못하면 `SPECIES_FILTERS` 는 손대지 않고
2·3번만 진행한다. 검증 안 된 코드는 넣지 않는다.
