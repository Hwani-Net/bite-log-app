## 공통 실행 프로토콜 (모든 GOAL 동일)

1. **구현** — CLAUDE.md 11단계 파이프라인 순서 엄수
2. **검증 게이트** (전부 통과해야 다음 단계):

   - `npx vitest run` — 전체 통과 (신규 로직은 유닛 테스트 동반 필수)

   - `npm run build` — 에러 0
3. **실패 시** — 수정 후 재검증, GOAL당 최대 3회. 3회 실패 시 즉시 중단하고 `GOAL-N BLOCKED: <사유>` 보고 (무한 재시도 금지)
4. **커밋** — Conventional Commits, GOAL당 논리 단위 커밋

GOAL별 diff를 `--prompt`로 전달해 리뷰를 받는다. **2026-08-26 사용자 명시 지시로 결정** — `central/OPENROUTER-TOOLBOOK.md`의 "데이터 정책 미공개, 공개 가능한 내용만" 권고는 이 프로젝트 리뷰 용도에 한해 사용자가 직접 오버라이드함. 점수 산정·재검수 기준은 기존 7/10 문턱 유지
6. **배포·확인** — `vercel` 배포 → 라이브 URL 200 + 해당 화면 스크린샷 확인
7. **상태표 갱신** — 아래 표의 상태를 DONE으로, 증거 열에 커밋 해시 + 검증 결과 한 줄

## GOAL 정의

각 GOAL: 범위 / 수용 기준(관찰 가능) / 검증 / 회귀 케이스.

### GOAL-1 · 내 선사 카드 저장 구조 + 즐겨찾기 (A2+N1 기반)

- **범위**: `src/services/myBoatService.ts` 신설 — localStorage 기반, 배 uid 키 저장 구조 하나:
  `{ favorite, verdict: 'again'|'ok'|'never'|null, memo, rides: [{date, memo}], snapshots: [{name, port, priceLine?, seenAt}] }`
  BoatListingCard·배 상세 페이지에 별(즐겨찾기) 버튼. /booking 상단에 "즐겨찾는 선사" 섹션.
- **수용 기준**: ① 별 클릭 → 새로고침 후에도 유지 ② 즐겨찾기 배가 상단 섹션에 카드로 표시 ③ 즐겨찾기 해제 시 섹션에서 제거
- **검증**: 유닛 — store CRUD·직렬화. e2e — 별 클릭 → reload → 즐겨찾기 섹션에 해당 배 이름 존재.
- **회귀**: 기존 booking e2e 8개 전부 통과. 기존 빈자리 알림 watchlist와 키 충돌 없음.

### GOAL-2 · 승선 이력·판정 UI + 배지 + de-rank (N1+N4)

- **범위**: 배 상세 페이지에 판정 3버튼(또 탄다/보통/안 탄다) + 한 줄 메모 + "탄 날짜 추가". 검색 카드에 배지(⭐ N회 승선·다시 타고 싶음 / ⚠️ 다시 안 탐). 검색 결과 정렬에서 'never' 배는 하단 + 흐림 처리(숨김 아님).
- **수용 기준**: ① 판정 저장 → 검색 결과 카드에 배지 표시 ② 'never' 배가 목록 최하단으로 이동하고 시각적으로 흐림 ③ 메모가 배지 옆/상세에 노출
- **검증**: 유닛 — 정렬 함수(never 하단, 나머지 원래 순서 유지). e2e — 판정 저장 후 /booking 복귀 → 배지 텍스트와 카드 순서 단언.
- **회귀**: 판정 없는 배들의 기존 정렬 불변.

### GOAL-3 · 변경 감지: 이름·모항·가격 + 소멸 (N2+N3+N6)

- **범위**: 배 상세 조회·즐겨찾기 시점마다 snapshot 자동 추가(같은 값이면 중복 저장 안 함). 상세 페이지에서 최신 meta와 마지막 snapshot 비교 → 달라지면 배너 "이 배는 이전에 '스텔라호(대천포항)'였습니다" / "지난 조회 대비 가격 변동". 즐겨찾기 배의 상세 meta가 연속 부재(파싱 실패 아님이 확인된 빈 응답)면 "더 이상 등록되지 않은 배" 표시. uid 끊긴 배는 수동 연결 UI만(자동 매칭 금지 — C12).
- **수용 기준**: ① 이름이 다른 snapshot이 있으면 배너 렌더 ② 가격 변동 시 이전→현재 표기 ③ 같은 값 재조회 시 snapshot 개수 불변
- **검증**: 유닛 — snapshot diff 함수(이름/항구/가격 각각), 중복 방지. e2e — localStorage에 옛 이름 snapshot 주입 후 상세 진입 → 배너 텍스트 단언.
- **회귀**: snapshot 없는 첫 방문 배에서 배너 미표시.

### GOAL-4 · 키워드 통합 검색 (A1)

- **범위**: /booking 검색 입력 1개 — 이미 로드된 더피싱 결과 + 낚시뚜 디렉터리를 클라이언트에서 이름·항구(areaPath)·어종(fishTypes) 부분일치 필터. 서버 요청 추가 없음.
- **수용 기준**: ① "몬스터" 입력 → 두 소스 모두에서 매칭 카드만 표시 ② 입력 지우면 원상복구 ③ 매칭 0건이면 빈 상태 문구
- **검증**: 유닛 — 매칭 함수(이름/항구/어종 각 필드). e2e — 검색어 입력 → 표시 카드 전부가 검색어 포함 단언(개수 아님, 내용).
- **회귀**: 검색어 없는 상태의 기존 날짜·어종·권역 필터 동작 불변.

### GOAL-5 · 항구·정원 필터 (A3+A4)

- **범위**: 권역 선택 시 현재 결과의 areaPath에서 항구 목록 추출해 하위 칩 렌더(클라이언트 필터). capacity("12인승") 파싱해 소형(≤10)/중형(11~18)/대형(19+) 3칩.

- **검증**: 유닛 — capacity 파서(비정형 문자열 포함), 항구 추출. e2e — 칩 클릭 후 표시 카드 전부의 areaPath/정원이 조건과 일치 단언.
- **회귀**: 칩 미선택 시 전체 표시. 기존 서버측 권역·어종 필터와 중첩 동작.

### GOAL-9 · 출조 브리핑 연동 + 시즌 회귀 리마인더 (B7+N5)

- **범위**: preTripBriefingService 재사용 — 승선 예정(빈자리 알림·즐겨찾기에 날짜 있는 배)의 D-1에 날씨·물때·채비 브리핑 로컬 알림. 승선 이력의 월·어종과 시즌DB를 대조해 "작년 이맘때 ○○ 출조" 리마인더 카드.
- **수용 기준**: ① 예정일 D-1 조건에서 브리핑 알림 발생(테스트에선 시간 주입) ② 이력 월·어종이 현재 시즌과 일치하면 리마인더 카드 렌더
- **검증**: 유닛 — D-1 판정·시즌 일치 판정(시간 주입 가능하게). e2e — 이력 주입 후 /booking에서 리마인더 카드 단언.
- **회귀**: 이력 없는 사용자에게 카드 미표시. 기존 알림 폴링 동작 불변.

### GOAL-10 · 출항 취소 조기 경보 (N8)

- **범위**: 예정 승선일 D-3~D-1의 해당 해역 예보(풍속·파고, 기존 날씨 서비스)가 임계 초과면 "출항 취소 가능성" 알림 + 같은 배의 대안 날짜(달력에서 자리 있는 날) 제시.
- **수용 기준**: ① 임계 초과 조건에서 경보 발생(테스트에선 예보 주입) ② 경보에 대안 날짜 최대 2개 포함 ③ 임계 이하면 무알림
- **검증**: 유닛 — 임계 판정·대안 날짜 선정. e2e — 예보 mock 주입 화면에서 경보 카드 단언.
- **회귀**: 예보 데이터 결측 시 조용히 생략(오탐 경보 금지).

## 루프 안전 (중앙 규칙 준수)

- 반복 상한: 루프 1회 = GOAL 1개, 최대 10회(GOAL 수). 무제한 반복 금지.
- GOAL당 수정 재시도 상한 3회 — 초과 시 `GOAL-N BLOCKED` 보고 후 정지.
- 종료 토큰: 전 GOAL DONE 시 `ALL GOALS DONE`, 차단 시 `GOAL-N BLOCKED: <사유>`.
- 상태는 이 문서의 상태표가 단일 진실 — 세션이 바뀌어도 표만 읽으면 이어서 실행 가능.
